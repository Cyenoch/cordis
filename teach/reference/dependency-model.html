依赖模型速查

“插件依赖插件”在 Cordis 里是三个独立问题：能不能装（包）、什么时候能跑（服务）、谁先停（父子）。

三层对照

① 服务需求② 包依赖③ 父子所有权
声明在 Definition.Requires + manifest definitions[].requires manifest dependencies / optionalDependencies 宿主 Entry.Parent；作者 contract.CreateChild
检查时机 每次启动：未满足就 waiting；运行中 provider 退役则退回 waiting 安装/选择/启用前的 Store.Preflight 启动顺序与停用顺序
不满足时 实例 state: waiting，WaitingFor: ["name@major"] 必需：直接报错；可选：Status.Diagnostics 一条诊断 子实例等父；父退役回收子树
匹配规则 名 + major 相同，minor ∈ [MinMinor, MaxMinor] ID + 严格 SemVer：[Min,Max) 或比较器 >=1.2.0 <2.0.0 ID 唯一；父 ID 必须存在
调用/管理 API scope.Call、sdk.Call[In,Out]、typed client Host.Install/Select、Store.Preflight Instance.Stop/Retry、Host.Disable、ChildInstance.Wait/Update
典型错误 把包装上就以为能调用；minor 写成精确值 “已安装”当成“已选择”；用服务名当包 ID 用子实例去做服务依赖解析（它不参与）

① 服务依赖：区间算术

provider:  contract.Service{Name: "chain.a", Major: 1, Minor: 2}
consumer:  contract.Requirement{Name: "chain.a", Major: 1, MinMinor: 1, MaxMinor: 3}

Accepts(provider) = name 相同 && major 相同 && 2 ∈ [1,3]  → true
provider minor 0  + requirement [1,3]                          → false（waiting）
provider major 2  + requirement major 1                        → false（永不匹配）

examples/plugins/chain 故意提供 minor 2、要求 [1,3]，用来证明匹配不是“精确等于”。

两个版本体系，不要混

服务版本 = 名 + major + minor 区间，决定运行时绑定；包版本 = 严格 SemVer（可带 ^/~ 比较器），决定能不能安装/选择。manifest 的 definitions[].provides 与代码里的 Provides 必须一致，否则发布时声明不齐。

② 包依赖：Preflight 的实际判定

情况结果真实文案（源码格式串）
必需依赖未安装/未选择错误%s requires missing selected package %s
已选择但版本不在区间错误%s requires %s [%s,%s), selected %s
依赖环错误package dependency cycle at %s（正常 Select 会先拒绝对端的依赖，通常到不了这一步）
可选依赖缺失诊断%s: optional dependency %s is not selected
可选依赖版本不兼容诊断%s: optional dependency %s version %s is incompatible

诊断不会阻止启动，但会出现在 Instance.Status().Diagnostics；不要因为“能跑”就丢弃它。

③ 父子：两种子实例

宿主编排作者创建
APIEnable(Entry{Parent: "parent.id"})contract.CreateChild(ctx, scope, Child{...})
持久化是，进 catalog；Restore 需宿主显式恢复否，绑定当前 activation，重启父时重建
停用Disable(parent) 持久停用整棵子树父退役自动回收；新 activation 的旧 handle 失效
启动顺序父先于子；子未就绪不阻塞父同左；初始化里 Wait 自己的子实例会得到 reentrant_call
数量上限—每个 activation 最多 256 个直接子实例

可见性：realm

服务沿 realm 树向后代可见；ConfigureRealm(name, parent, isolatedKeys) 里的隔离键不继承父 realm。因此“包已安装、实例也 active，但调用总等不到 provider”的第一嫌疑是 realm，而不是版本。

依赖链示意（examples/plugins/chain）

consumer C ──requires chain.b@1 [1,3]──▶ middle B ──requires chain.a@1 [1,3]──▶ provider A
     │                                       │                                   │
     └────── 先启用 C，再 B，最后 A：C/B 先 waiting，A 发布后逐个收敛 ──────────────┘
                                            每层都 Provides minor 2

optional-parent ──CreateChild("optional", Definition:"middle")──▶ 更晚到达也能 Wait 成功
