类型安全吗？

半分安全：每个进程内部由 Go 编译期保证；跨进程没有类型系统，只有四道会把错配变成显式失败的闸门。

先把“安全”拆成两半

宿主和插件是两个独立 module（examples/plugins/counter/go.mod 用 replace 指向本仓库），宿主编译时看不到插件的类型。所以：

  • 进程内：sdk.Provide[In, Out] 让作者拿到真实的 Go 类型，写错字段是编译错误。
  • 跨进程：唯一共享的是 JSON + 名字/版本。宿主侧 host.Call 拿回的是 json.RawMessage——类型由你的解码决定，不是框架猜的。
// 插件侧：编译期类型
sdk.Provide(scope, contract.Service{Name: "demo.greet", Major: 1},
    func(ctx context.Context, req Request) (Response, error) { … })

// 宿主侧：边界只给字节
out, err := host.Call(ctx, "", contract.Requirement{Name: "demo.greet", Major: 1}, input)
var resp Response
if err := contract.Decode(out, &resp); err != nil { /* 显式失败 */ }

四道闸门

闸门触发点拦住的样子
生成阶段cordis generate / schema.Compile$ref、allOf、名称冲突：生成不出文件
注册阶段sdk.Provide → contract.CheckDataTypeservice type int64 requires an explicit decimal-string codec
编解码期contract.Decode/Encode未知字段、重复 key、尾随数据、深度 > 32
业务错误Handler 返回 contract.Fail(...)invalid_message、denied、timeout …

细节（允许/禁止类型全表、严格 JSON 规则、错误码）见 类型边界速查。

练习：它会被哪道闸门拦住？

点一个选项即可得到反馈；点错可以继续试。Esc 重置当前题。

① 插件作者把请求体写成 struct{ N int64 }。
CheckDataType 在注册时拒绝裸 64 位整数，要求显式十进制字符串 codec。
② 宿主发来 {"value":1,"extra":true}，插件 struct 里没有 extra。
Decode 开 DisallowUnknownFields：未知字段是错误，不会静默丢弃。
③ 契约文件里写了 "$ref": "#/definitions/x"。
受限 schema 明确拒绝 $ref；不合规输入不会写出半份文件。
④ 响应类型是 map[int]string。
map key 必须是 string；注册时就会报 service map keys must be strings。
⑤ 请求 JSON 里同一个字段出现两次。
重复 key 属于解码期错误：框架不接受“后者覆盖前者”的运气。
⑥ 插件拒绝这次调用，返回 contract.Fail(contract.Denied, …)。
这是显式业务结果：调用方拿到 *contract.Error，errors.As 可读 Code。

为什么 int64 不能用裸 JSON number？

JSON 数字在通用解码里会落到 float64，超过 253 的整数会静默丢精度（见 encoding/json 对 interface{} 的说明）。Cordis 的选择是在注册期就拒绝，让作者显式用十进制字符串表达 64 位整数；生成器对 format:"int64" 还要求规范十进制（无前导 +/0）。

既然跨进程没有类型系统，为什么还说“类型安全”？

因为安全性可以退化为可观测的失败：错配必须在注册期或解码期报错，而不是变成零值、静默截断或“看起来成功”。Cordis 的取舍是把四道闸门都做成硬失败，并用生成契约让两边共享同一份约束。

这一课你该带走的

看到类型问题时，先问“哪道闸门”：写不出/编译不过是生成阶段，启动即失败是注册阶段，调用报 JSON 错误是编解码期，拿到业务错误码是业务层。定位对了，修法基本唯一。
