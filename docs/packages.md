# 外部插件包

包是 ZIP，包含 `plugin.json`、产物、`integrity.json`，签名包还包含 `signature.json`。作者维护 TOML、YAML 或 JSON 声明，由 CLI 构建和打包，机器 Manifest 描述定义、配置 schema、服务版本和 native 目标。

## 发行文件

Pack 只收集元数据、`runtime.artifacts` 声明的全部产物及顶层 `resources` 指定的运行文件。例如：

```toml
resources = ["assets/message.txt", "templates/page.html"]
```

资源路径相对于作者目录，必须是精确的普通文件路径；不支持目录或 glob，重复、链接、越界、与产物或保留元数据冲突均报错。省略清单表示没有额外资源。源码、开发配置、日志和私钥不会仅因为位于目录内就进入 ZIP；显式列入资源的内容仍由发布者负责。

Pack 在私有快照校验作者声明、生成代码、build.json、实际 SDK 和所有声明目标，再生成发行目录。这些校验输入不必进入 ZIP；缺少或修改生成文件仍会导致打包失败。打包失败或取消保留已有 archive。

`cordis inspect ARCHIVE.zip` 返回 `files` 清单，包括路径、大小、SHA-256，以及包引用和 Manifest。它校验包内容，不为发布者授予信任。完整性表和签名文件自身也列在检查结果中，但不递归纳入签名输入。

## 版本与契约

包版本是发行 semver；服务版本是 major/minor；消费者还声明接受的 minor 闭区间。这三者分别决定包选择、服务绑定和方法契约。

包没有应用权限、贡献或业务数据版本字段。

## 完整性与来源

完整性表覆盖所有包文件。校验拒绝路径穿越、链接、重复路径、大小超限和摘要不符。Ed25519 签名输入使用 `cordis-go-package/v1` 域、排序后的 UTF-8 路径、大小与摘要，避免依赖 JSON 文本排序。包摘要是这份签名输入的 SHA-256，`integrity.json` 与 `signature.json` 不在其中。

## 信任

Host 用 `packagehost.TrustPolicy` 决定信任哪些包。包被信任需要同时满足：

1. 发布者不在 `RevokedPublishers` 里，并且 `Publishers[发布者]` 列出了该包 ID。
2. 包摘要在 `Digests` 里；或者包签名来自 `Keys` 中一把未撤销、属于该发布者的密钥，并且验证通过。

信任检查之前，包先通过格式检查：完整性、Manifest，以及存在时的 `signature.json`。`signature.json` 不是 JSON、有重复或未知字段时，包格式错误，摘要批准也不放行。

`Digests` 批准的是确切内容，单独就够，生产与开发都适用。它只跳过签名的信任与密码学验证：没有签名、密钥未知或已撤销、属于别的发布者、签名值无法解码或验证失败，结果都一样。签名文件不在摘要里，谁都能加上或删掉它，所以削弱不了摘要批准。ID 和发布者写在 `plugin.json` 里，受摘要保护，摘要批准因此不绕过第 1 条。不用签名、由用户逐个确认包的宿主只需填写 `Publishers` 与 `Digests`，确认前用 `Inspect` 取得摘要。

Store 记下每个包 ID 第一次安装时的发布者，卸载后仍保留。之后安装同一 ID、发布者不同的包，需要 `PublisherChanges[包 ID][新发布者]`；装上后 Store 改记新发布者，换回原发布者同样需要批准。

安装、选择预检和每次执行快照都按当时的策略重新校验。`Store.UpdateTrust`（经 Host 时为 `host.UpdateTrust`）更新策略后，下一次快照在精确摘要批准与有效的受信任签名都不成立时被拒绝：只撤销签名密钥，摘要仍被批准的包照常运行；只撤回摘要批准，仍带有效受信任签名的包也照常运行。撤销发布者，或撤回它对该包 ID 的授权，总是先于两者生效并拒绝。策略由宿主在每次打开时提供，Store 不保存它。

开发命令 `run -dev-unsigned` 与 `dev` 只批准本次产物的摘要，不修改全局信任。签名不限制 native 代码行为。

## 安装与运行

Install 添加不可变内容，不改变已选版本。Select 显式选择；Enable 校验配置并记录启用意图。启动使用私有快照，避免运行期间源目录被修改。

native 可通过 `CORDIS_PACKAGE_DIR` 环境变量定位本次 activation 的包快照，再用标准库读取相对资源。运行工作目录仍独立；不要把包快照当作持久业务数据目录。

Replace 在停止旧实例前校验新包和现有配置。新版本初始化失败时保持可观察失败，不暗中回滚选择或业务行为。应用可以显式选择或替换回另一份代码。

卸载拒绝仍在使用的包和被启用依赖需要的包。调用者先显式停用相关实例，不存在计划后确认式级联。文件被操作系统占用时，返回 Pending 并保留待删除记录。

包目录只存代码、配置意图、完整性和运行记录。应用数据的保存、迁移和删除由应用负责。
