# framework-execution Specification

## Purpose

定义 native 插件进程的初始化、双向服务调用、事件和停止协议，以及 Go 作者启动入口；进程由用户选择运行，不承诺权限隔离。

## Requirements

### Requirement: Native 进程执行
框架 SHALL 仅执行匹配目标平台的 native 产物，每次激活独占进程。不支持的 runtime 或平台 MUST 在执行前失败。native 插件具有启动用户权限。

#### Scenario: 双实例原生插件
- **WHEN** 同一包启用两份不同配置实例并停用其中一份
- **THEN** 两份实例分别运行，停用其中一份不影响另一份

### Requirement: 标准会话与身份
所有插件 SHALL 使用标准会话，在业务调用前协商协议与 frameBytes，并绑定宿主分配的包、实例、激活和摘要。未知必需特性及预算不匹配 MUST 拒绝，不提供专属宿主协议适配。

#### Scenario: 初始化预算不一致
- **WHEN** 插件未确认宿主提出的 frameBytes
- **THEN** 会话失败，不发布服务或启动受管工作

### Requirement: 有界消息与取消
协议 SHALL 校验消息结构、方向、关联身份、大小与在途数量；日志不得混入 stdout。业务取消通知对端。发送前发现普通结果过大 SHALL 仅失败当前调用；收到畸形帧则终止对应会话。

#### Scenario: 单次结果过大
- **WHEN** 一个业务结果编码超过帧预算，随后发起正常调用
- **THEN** 前次调用得到错误，后次调用仍正常完成

### Requirement: 单一 SDK 入口
Go 作者 SHALL 使用返回错误的 sdk.Run 运行一个或多个定义，统一信号、标准输入输出和清理。内存协议测试使用显式 transport 入口；框架不替作者调用 os.Exit。

#### Scenario: 进程取消
- **WHEN** 插件运行期间父 context 取消或收到终止信号
- **THEN** 已登记资源完成清理，错误返回给 main 处理

### Requirement: 类型化契约
生成器 SHALL 从单一作者声明生成配置、服务和消费者范围；严格数据校验在输入边界完成。builtin、native 和子实例省略配置均规范化为空对象且仍需符合定义 schema。

#### Scenario: 配置类型不匹配
- **WHEN** 某定义收到只符合另一份定义的配置
- **THEN** 在停止旧实例或启动插件前返回字段错误

### Requirement: native 订阅控制与发布门控
标准会话 SHALL 支持带订阅身份的登记、取消和逐监听者投递；订阅归属取自宿主分配的当前 activation，不接受插件指定另一实例。初始化订阅随发布生效，初始化失败不留下监听者；Active 期间新增订阅确认后可用，退役后拒绝新增。发送取消订阅失败 SHALL 明确返回错误，不假报远端已取消。

#### Scenario: 初始化失败
- **WHEN** native 在初始化时登记监听者后失败
- **THEN** 外部事件不能投递给该监听者，未发布订阅随失败清理，不遗留在 Host

#### Scenario: 退役后迟到登记
- **WHEN** 旧 native 激活的订阅请求在退役或同 ID 实例重建后到达
- **THEN** 该请求不能登记到新激活，错误可观察；新激活订阅不受影响

### Requirement: 跨执行方式一致的事件行为
builtin 和 native SHALL 使用相同的逐监听者登记次序、once/prepend、取消和三个 dispatch 规则；同一 native 内的不同监听者不得被折叠成一个不透明结果。Host 是唯一的监听者准入决策点；会话发送次序和 SDK 接收时引用获取 SHALL 保证取消确认不能使已准入投递丢失回调，已准入引用只在投递结束或会话清理时释放。事件回调继续占用实例串行执行槽，取消/登记等控制消息不等待业务槽或回调完成。跨实例同步事件形成调用环时 SHALL 返回已有环检测错误，而非重入执行。

#### Scenario: 混合监听者结果
- **WHEN** builtin 与 native 各自登记多个监听者并使用 Sequential 或 Parallel 发射
- **THEN** 返回逐监听者结果，错误能定位实际监听者；不得只保留 native 的首个 Handled 结果

#### Scenario: native 回调自取消
- **WHEN** native 监听函数取消自身订阅
- **THEN** 控制消息不因等待同一业务槽而死锁；当前函数继续结束，后续发射不能新准入它

#### Scenario: 取消与已准入投递竞争
- **WHEN** Host 已准入 native 投递，SDK 尚未进入该回调，同时宿主确认取消订阅
- **THEN** 该次投递仍持有回调引用，不变成未知订阅；后续发射不再准入，完成后释放引用，不无限保留已取消回调

#### Scenario: once 与取消竞争
- **WHEN** once 在 Host 被消费后，插件在接收前取消，或在回调中及结束后再次取消该句柄
- **THEN** 合法取消都成功且不等待当前回调，监听者最多执行一次；在途引用结束后可释放，无需永久订阅墓碑

### Requirement: 有界的动态订阅消息
新增订阅协议 SHALL 复用既有结构、身份、帧预算和在途请求校验；每个 activation 的活动订阅有明确有限上限，取消释放相应名额，在途引用继续受既有 inflight 约束。协议中缺失、非法、重复登记或不属于本激活的订阅身份 MUST 明确失败；格式合法的当前 activation 订阅取消若已不活动 SHALL 返回 inactive，SDK 对其持有句柄将该结果视为幂等成功。不创建占位监听者，也不为未知订阅投递成功结果。

#### Scenario: 动态订阅达到上限
- **WHEN** 插件活动订阅达到上限后继续登记
- **THEN** 新登记被拒绝，现有调用和订阅仍可用；取消一个后可再次登记

#### Scenario: 伪造投递或控制身份
- **WHEN** 消息引用另一激活的订阅身份或包含非法必需字段
- **THEN** 按既有协议错误分类拒绝，不撤销或触发其他实例的订阅

### Requirement: 进程结果的结构化来源
native 执行层 SHALL 向 Host 提供结构化退出信息及带激活身份的 stderr 转发，保留已有错误链。强制终止标记只能来自实际终止动作，signal 只在操作系统提供时填写；无法获知字段 SHALL 明确为空，不从错误文本猜测。日志失败不免除进程和管道回收。

#### Scenario: Windows 进程退出
- **WHEN** Windows 插件以非零码结束而平台没有对应 signal
- **THEN** 返回实际退出码、空 signal 和意外退出类别，不填入伪造的 Unix signal

#### Scenario: 宽限期耗尽
- **WHEN** native 不响应停止，执行层宽限期后确实强制终止并回收
- **THEN** 结果显示请求停止及发生强制终止的事实；不能只返回普通成功停止
