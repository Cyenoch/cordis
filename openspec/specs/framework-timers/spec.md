# framework-timers Specification

## Purpose
定义归属调用方实例的定时辅助：延时、周期、等待、节流与防抖都随实例停止自动取消，回调与实例的停止过程不竞争。

## Requirements

### Requirement: 延时与周期回调
定时辅助 SHALL 以调用方作用域登记延时一次或按周期重复的回调，并返回可提前取消的句柄。回调归属该作用域的实例：实例尚未 Active 时不触发，实例的 context 取消后不再触发，停止过程等待正在执行的回调结束。回调中的 panic SHALL 使该实例失败而不终止进程。

#### Scenario: 延时触发一次
- **WHEN** 插件登记一个延时回调并保持运行超过该延时
- **THEN** 回调恰好执行一次

#### Scenario: 提前取消
- **WHEN** 插件登记周期回调，触发两次后取消句柄
- **THEN** 之后不再触发；重复取消没有副作用

#### Scenario: 在回调里取消自己
- **WHEN** 周期回调在自己的执行过程中取消自己的句柄
- **THEN** 取消立即返回，当前这次执行正常结束，之后不再触发

#### Scenario: 随实例停止
- **WHEN** 插件登记周期回调后被停止
- **THEN** 实例的 context 取消后回调不再触发；若此时回调正在执行，实例的清理在它返回之后才运行

#### Scenario: 一次性回调不留痕迹
- **WHEN** 插件先后登记大量延时回调，它们全部触发完毕
- **THEN** 实例上不再保留与这些回调对应的登记或后台工作

### Requirement: 可取消的等待与节拍序列
定时辅助 SHALL 提供随 context 取消的等待，以及可迭代的节拍序列。等待在时长到达时正常返回，context 先取消时返回其错误。节拍序列在 context 取消时结束；消费者处理慢于周期时 MUST 丢弃多余的节拍而不积压。

#### Scenario: 等待被取消
- **WHEN** 插件用实例的 context 等待一段时间，实例在到时之前被停止
- **THEN** 等待立即返回取消错误

#### Scenario: 慢消费者
- **WHEN** 消费者每次处理节拍的耗时为周期的三倍
- **THEN** 消费者收到的节拍数少于经过的周期数，序列在 context 取消后结束且没有残留的后台工作

### Requirement: 节流与防抖
定时辅助 SHALL 提供节流与防抖包装。节流在窗口内首次调用时立即执行，窗口结束时以窗口内最后一次的参数再执行一次，并可选择不做这次尾随执行；防抖在最后一次调用之后静默满指定时长才执行一次。两者归属调用方实例，实例停止后的调用 MUST 不产生任何执行。

#### Scenario: 节流
- **WHEN** 在一个节流窗口内以参数 1、2、3 连续调用
- **THEN** 回调先以 1 执行一次，窗口结束时以 3 执行一次，共两次

#### Scenario: 不做尾随执行的节流
- **WHEN** 以“不做尾随执行”的方式节流，并在一个窗口内以参数 1、2、3 连续调用
- **THEN** 回调只以 1 执行一次

#### Scenario: 防抖
- **WHEN** 以小于静默时长的间隔连续调用三次，之后不再调用
- **THEN** 回调在最后一次调用之后静默期满时以最后一次的参数执行一次

#### Scenario: 停止后的调用
- **WHEN** 实例停止后再调用节流或防抖包装
- **THEN** 回调没有被执行
