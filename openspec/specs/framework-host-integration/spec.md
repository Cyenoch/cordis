# framework-host-integration Specification

## Purpose

Cordis 作为独立 MIT Go module 提供代码、中文文档、CLI 与可复现验收，不引用具体应用项目，示例只演示通用组合和 native 插件开发。

## Requirements

### Requirement: 独立项目与文档
公开文档、代码和验收 SHALL 只描述 Cordis 自身契约，不依赖或命名具体宿主应用。文档与示例 MUST 使用当前 API。只读上游参考源码不修改。

#### Scenario: 独立检出
- **WHEN** 仅检出 Cordis 并运行文档示例和验收
- **THEN** 无需相邻应用仓库或专属协议适配器

### Requirement: 可复现验收
通用验收 SHALL 覆盖 Go 测试、race、独立 native 构建与生命周期运行。报告 MUST 只声明实际运行过的平台，Windows 入口与 POSIX 入口保持相同范围。声明支持的 Linux amd64/arm64、macOS amd64/arm64、Windows amd64 SHALL 在对应平台真实运行验收，记录准确提交与 CI 链接，不能以交叉编译替代执行。

#### Scenario: 执行验收
- **WHEN** 在当前开发平台执行通用验收脚本
- **THEN** 实际构建原生插件并验证双实例、依赖、更新与清理，输出真实平台

#### Scenario: 新能力跨平台验证
- **WHEN** 本变更准备声明完成
- **THEN** 五平台实际验证签名包安装、CLI 意图与前台运行、native 崩溃分类、dev 编辑重启、作用域绑定、动态 child 控制及事件取消；报告逐项成功/失败/未执行，不沿用旧提交结果冒充新增能力通过

### Requirement: 文档工具链
中文文档站 SHALL 保留导航、搜索、构建变量与代码示例校验；删除的 API 不得继续作为教程入口。

#### Scenario: 构建文档
- **WHEN** 文档站执行检查和生产构建
- **THEN** 内部链接和当前示例通过校验，删除页面不出现在导航中

### Requirement: 可执行的开发与运维流程
文档 SHALL 提供可执行的签名包离线管理→前台运行、单包 dev、故障定位、动态子树检查、显式失败恢复和版本回退流程。说明日志包含用户错误文本的风险、原始 stderr 的显式授权、关闭与强制终止限制；不把资源清理或回退代码表述成业务回滚。

#### Scenario: 无 Go 宿主代码的首次运行
- **WHEN** 新用户按教程构建插件、打包签名、配置公钥授权、安装选择并启用后执行 host
- **THEN** 能运行插件并看到其归属状态；中断后退出，离线 status 不再将最近运行记录称为当前运行状态

#### Scenario: 真实故障定位
- **WHEN** 教程中的测试插件初始化失败或非预期退出
- **THEN** 用户能从结构化记录定位包、entry、activation 和阶段，并按教程手动处理；没有无条件自动重启或重放

### Requirement: 公开能力边界
文档 SHALL 按可观察场景说明与固定版本官方 Cordis 的对应与差异，不宣称完全兼容。明确服务隔离不是权限边界、事件仍默认 Host 广播、替换重建 activation、动态 child 不单独持久化，以及离线 CLI 不控制运行中应用；本机在线控制必须显式授权。跨进程 waterfall、intercept、远程管理、HMR 与配置回写不得被文案暗示已实现。

#### Scenario: 查询同名服务组合教程
- **WHEN** 用户阅读双组同名服务的教程
- **THEN** 能识别哪些 service key 被隔离、哪些仍共享，以及事件未随服务自动隔离，不需要猜测父子关系是否自带隔离

#### Scenario: 选择管理入口
- **WHEN** 用户阅读运行管理教程
- **THEN** 能分别执行空闲 Store 的离线命令和运行中 Host 的本机认证控制，不需要绕过锁或猜测端口；文档说明连接凭据不授予 native 沙箱能力

### Requirement: 带版本的 CLI 交付
项目 SHALL 提供 Linux amd64/arm64、macOS amd64/arm64、Windows amd64 的 CLI 下载归档及 SHA-256 校验和，包含许可证、版本和来源提交。版本输出 MUST 与发行 tag 一致，预发布明确标记。发布 SHALL 仅使用完成五平台验收的同一提交；失败不能公开不完整发行集，重跑不覆盖已发布的同名资产。

#### Scenario: 首次预发布
- **WHEN** 首个预发布提交通过验收并执行发布流程
- **THEN** GitHub Release 可下载五个平台的归档与校验和，版本、来源提交可核对，预发布不标为稳定最新版

#### Scenario: 一个目标失败
- **WHEN** 任一平台构建、运行或校验失败
- **THEN** 不将部分产物公开为一次完成的发行

#### Scenario: 下载并运行
- **WHEN** 用户在对应平台下载、验证校验和、解压并执行 version/help
- **THEN** CLI 可直接运行，报告正确 tag 和提交，归档包含 MIT 许可

### Requirement: 可执行的插件发布示例
中文文档 SHALL 提供多平台作者声明、完整构建、检查、打包签名、公钥授权和安装运行示例。自动验收 SHALL 构建所有声明目标并在当前平台执行签名包。临时测试私钥仅用于该次测试；文档不得要求将生产私钥放进源码或发行目录。

#### Scenario: 按示例交付插件
- **WHEN** 发布者按示例构建两种以上目标并签名，接收者使用明确公钥授权安装
- **THEN** 包内目标齐全，接收者可运行本机目标和资源；未获授权的相同签名仍被拒绝

#### Scenario: 来源与证据一致
- **WHEN** 记录发布验收结论
- **THEN** 报告实际源码提交、测试平台和 CI 结果；不能将交叉编译描述成其他平台实际运行

### Requirement: 可执行的多包开发教程
文档 SHALL 提供两个独立 native 作者包组成开发环境的可执行示例，覆盖显式清单、跨包服务依赖、配置修改、编译失败和整组重启。明确单包入口仍可用，project 仅用于开发，不是生产部署或远程依赖下载功能。

#### Scenario: 联合开发完整循环
- **WHEN** 用户按教程启动 provider 与 consumer，再修改 provider 的行为
- **THEN** consumer 在新组中使用更新后的 provider；编译错误时旧组仍工作，退出后两个进程均回收
