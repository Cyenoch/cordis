# framework-logging Specification

## Purpose
定义内核上的日志服务：插件以自己的作用域取得带有实例名称的标准库日志器，应用可按名称控制级别并挂接输出目标。

## Requirements

### Requirement: 按调用方命名的日志器
日志服务 SHALL 为调用方作用域返回标准库的结构化日志器，其记录带有日志器名称。名称默认取自调用方实例的名称，可由作用域设置覆盖，内层设置优先。同一调用方多次取得的日志器 SHALL 行为一致。

#### Scenario: 默认名称
- **WHEN** 名为 http 的插件用自己的作用域取得日志器并写一条记录
- **THEN** 输出的记录中日志器名称为 http

#### Scenario: 设置覆盖名称
- **WHEN** 应用用作用域设置把名称设为 api 后在该作用域加载插件，插件取得日志器并写一条记录
- **THEN** 输出的记录中日志器名称为 api

### Requirement: 级别过滤与就地调整
日志服务 SHALL 按“调用方作用域设置的级别，否则该名称的级别，否则默认级别”决定是否输出一条记录。更新日志插件的配置 MUST 就地生效：不重启日志插件，也不重启依赖它的插件，已经取得的日志器随之改变行为。

#### Scenario: 按名称的级别
- **WHEN** 默认级别为 info，名称 db 的级别为 debug，db 与 http 两个日志器各写一条 debug 记录
- **THEN** 只有 db 的记录被输出

#### Scenario: 作用域设置的级别
- **WHEN** 默认级别为 info，应用用作用域设置把某个分组的级别设为 debug，分组内外各有一个插件写一条 debug 记录
- **THEN** 只有分组内插件的记录被输出

#### Scenario: 运行期调级
- **WHEN** 把默认级别从 info 更新为 debug，随后一个早先取得的日志器写一条 debug 记录
- **THEN** 该记录被输出；依赖日志服务的插件的启动函数没有再次执行

### Requirement: 输出目标
日志服务 SHALL 默认把记录以文本或 JSON 格式写到标准错误，MUST NOT 写到标准输出。任何持有作用域的代码 SHALL 可挂接额外的输出目标；该目标归属挂接它的实例，实例停止时自动移除。一个输出目标的错误 MUST NOT 影响其他目标和写日志的插件。

#### Scenario: 挂接的目标随实例移除
- **WHEN** 插件挂接一个输出目标并收到记录，随后该插件被停止，之后再有记录写入
- **THEN** 停止之前的记录到达该目标，停止之后的记录不再到达

#### Scenario: 目标出错
- **WHEN** 两个输出目标中的一个在处理记录时返回错误
- **THEN** 另一个目标仍收到该记录，写日志的调用正常返回

#### Scenario: 输出目标自带级别
- **WHEN** 挂接一个只接受错误级别的输出目标，随后写入一条 info 记录和一条错误记录
- **THEN** 该目标只收到错误记录，默认输出两条都有

#### Scenario: 不占用标准输出
- **WHEN** 日志插件以默认配置运行并输出若干记录
- **THEN** 标准输出没有任何内容

### Requirement: 最近记录
日志服务 SHALL 在有界的环形缓冲中保留最近通过级别过滤的记录，并可按时间顺序查询。缓冲容量由配置决定，超出时丢弃最早的记录。

#### Scenario: 超出容量
- **WHEN** 缓冲容量为 3，先后写入 5 条记录后查询
- **THEN** 返回最后 3 条，顺序与写入顺序一致

### Requirement: 生命周期记录
日志插件 SHALL 记录实例的状态转换：进入 Failed 以错误级别记录并带上错误，其余转换以调试级别记录。记录的名称为发生转换的实例名称。记录 MUST NOT 包含插件配置。

#### Scenario: 启动失败被记录
- **WHEN** 日志插件运行中，另一个插件启动失败
- **THEN** 输出一条错误级别的记录，名称为该插件的实例名称，包含失败原因，不包含其配置
