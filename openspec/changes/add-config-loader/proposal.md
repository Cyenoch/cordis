# Proposal

## Why

内核提供“在代码里加载插件”。官方 Cordis 的 loader、include 和 group 让一份配置文件描述整棵插件树，运行期可以增删改条目并写回文件，这是用配置组装应用、以及为应用做管理界面的基础。

## What Changes

- `loader` 包：一个内核插件，读取配置文件，把条目加载成实例树，并发布加载器服务。
- 显式的插件注册表：应用把 `cordis.Plugin[C]` 以名称登记，加载器按名称解析；可挂接其他解析器。`hosting` 提供解析器，使已安装的 native 包也能作为条目。
- 条目支持分组、禁用、条目级的依赖、作用域设置和服务隔离；原始配置严格解码到带默认值的类型化配置，错误定位到文件的行列。
- 运行期编辑接口（创建、更新、移除、移动）与写回：YAML 文件保留注释和顺序，原子替换；无法解析的文件不被覆盖。
- 重新读取：按条目标识做差异，只影响变化的条目；与未写出的运行期变更冲突时以文件为准。
- 嵌套配置文件及父文件对它的补丁，变更按归属写回对应文件。
- 就绪等待：等待全部条目稳定，以及“加载器空闲”的条件依赖。
- 文档的能力对照，以及用配置文件组装应用的教程和示例。

范围与非目标：

- 不提供配置中的表达式求值。官方用 JavaScript 表达式计算 `disabled`、`config` 等字段；Go 没有对应的运行期求值，条目字段都是字面值。也不做环境变量替换，需要时由应用在交给加载器之前处理配置内容。
- 修改条目的隔离、设置、条目级依赖或把条目移到另一个组，会重新加载该条目；官方在这些情况下就地切换而不重启。原因是内核的作用域在加载时固定。
- 不提供保留内存状态的热重载；改动插件源码仍然需要重新构建并重启进程。
- 写回只支持 YAML。JSON 与 TOML 文件可以读取，运行期编辑对它们返回只读错误。官方会整份重写 JSON；这里不做，因为解析不保留键的顺序，为 JSON 另写一套保序读写不值得。
- 不提供官方为就地切换上下文而设的扩展点（`loader/entry-init`、`loader/patch-context`、`loader/partial-dispose`）；提供条目树的变更事件。
- YAML 写回保留键、值、顺序和注释，不保证空行与对齐等排版不变。
- Host 的持久 entry（catalog）与 CLI 由各自的规格定义；加载器文件是另一份独立的意图来源，同一个 native 包可以经任一途径启用，但加载器不读写 catalog 中的 entry。
- 不新增 CLI 命令：进程内插件编译在应用自己的可执行文件里，由应用的 `main` 使用加载器。

上游观察：条目字段、分组、嵌套文件、补丁归属、冲突以文件为准、不可解析文件不覆盖、匿名条目按内容匹配，来自官方 `loader` 与 `include` 的源码和测试。注册表、解码到类型化配置、行列定位、保留注释的写回、只读格式和 native 解析器是本项目的决定。

## Capabilities

### New Capabilities

- `framework-loader`：配置文件驱动的插件实例树、运行期编辑、写回、重新读取和嵌套文件。

### Modified Capabilities

- `framework-host-integration`：“公开能力边界”说明：配置回写属于加载器管理的文件。

## Impact

- 公开 API：`loader` 包；`hosting` 的 `(*Host).Resolver()`。
- 代码：`loader` 及其测试、`hosting` 的解析器与在用集合、`contract` 与 `config`（严格解码的错误携带字段路径）、示例、文档。
- 依赖：不新增模块依赖；写回使用 `go.yaml.in/yaml/v3` 的节点接口。
- 前置：前三个 change 已归档（顺序见 `add-typed-composition-kernel` 的 proposal）。本 change 对 `framework-host-integration` 的修改以 `add-wire-streams-and-chains` 归档后的主规格为基础。
- 公开契约须经非作者独立审查；验收为 `bash conformance/run.sh` 及 CI 五平台实际运行。
