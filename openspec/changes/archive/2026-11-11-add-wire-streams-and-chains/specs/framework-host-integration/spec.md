# Spec Delta

## MODIFIED Requirements

### Requirement: 公开能力边界
文档 SHALL 按可观察场景说明与固定版本官方 Cordis 的对应与差异，不宣称完全兼容，并分别说明进程内内核与跨进程各自具备的能力。明确服务隔离不是权限边界、Host 事件仍默认 Host 广播、替换重建 activation、动态 child 不单独持久化，以及离线 CLI 不控制运行中应用；本机在线控制必须显式授权。跨进程可用的是端点、事件、查询、流式结果和中间件链；活对象服务、设置和隔离只在单个进程内有效。远程管理、HMR 与配置回写不得被文案暗示已实现。

#### Scenario: 查询同名服务组合教程
- **WHEN** 用户阅读双组同名服务的教程
- **THEN** 能识别哪些 service key 被隔离、哪些仍共享，以及事件未随服务自动隔离，不需要猜测父子关系是否自带隔离

#### Scenario: 选择管理入口
- **WHEN** 用户阅读运行管理教程
- **THEN** 能分别执行空闲 Store 的离线命令和运行中 Host 的本机认证控制，不需要绕过锁或猜测端口；文档说明连接凭据不授予 native 沙箱能力

#### Scenario: 区分进程内与 native 的能力
- **WHEN** 用户查阅与官方 Cordis 的能力对照
- **THEN** 能判断每项能力在单个进程内和跨进程时各自是否可用，不会把活对象服务、设置或隔离当作可跨进程
