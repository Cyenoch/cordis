# Spec Delta

## ADDED Requirements

### Requirement: 带版本的 CLI 交付
项目 SHALL 提供 Linux amd64/arm64、macOS amd64/arm64、Windows amd64 的 CLI 下载归档及 SHA-256 校验和，包含许可证、版本和来源提交。版本输出 MUST 与发行 tag 一致，预发布明确标记。发布 SHALL 仅使用完成五平台验收的同一提交；失败不能公开不完整发行集，重跑不覆盖已发布的同名资产。

#### Scenario: 首次预发布
- **WHEN** 首个预发布提交通过验收并执行发布流程
- **THEN** GitHub Release 可下载五个平台的归档与校验和，版本、来源提交可核对，预发布不标为稳定最新版

#### Scenario: 一个目标失败
- **WHEN** 任一平台构建、运行或校验失败
- **THEN** 不将部分产物公开为一次完成的发行

#### Scenario: 下载并运行
- **WHEN** 用户在对应平台下载、验证校验和、解压并执行 version/help
- **THEN** CLI 可直接运行，报告正确 tag 和提交，归档包含 MIT 许可

### Requirement: 可执行的插件发布示例
中文文档 SHALL 提供多平台作者声明、完整构建、检查、打包签名、公钥授权和安装运行示例。自动验收 SHALL 构建所有声明目标并在当前平台执行签名包。临时测试私钥仅用于该次测试；文档不得要求将生产私钥放进源码或发行目录。

#### Scenario: 按示例交付插件
- **WHEN** 发布者按示例构建两种以上目标并签名，接收者使用明确公钥授权安装
- **THEN** 包内目标齐全，接收者可运行本机目标和资源；未获授权的相同签名仍被拒绝

#### Scenario: 来源与证据一致
- **WHEN** 记录发布验收结论
- **THEN** 报告实际源码提交、测试平台和 CI 结果；不能将交叉编译描述成其他平台实际运行
