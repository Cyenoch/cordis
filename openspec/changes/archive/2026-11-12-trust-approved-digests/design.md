## Context

源码事实（`7cb8d3e`）：`TrustPolicy.verify`（`packagehost/format.go`）先要求发布者未被撤销、且 `Publishers` 授权它提供该包 ID。之后没有签名时，只有 `development` 为真且摘要在 `DevDigests` 中才信任；有签名时只看签名：密钥须存在、未撤销、属于该发布者并验证通过，`DevDigests` 不被查看。Store 安装时把未签名、摘要被批准的归档标为 Development，所以 `development` 条件对未签名包是多余的。

包摘要是 integrity 签名输入的 SHA-256，覆盖除 `integrity.json` 与 `signature.json` 外的全部文件，包括 `plugin.json` 中的 ID 和发布者。`signature.json` 可以被任何人加上、换掉或删掉，摘要不变。

安装（`Store.install`）、选择预检（`prepareSelection`）和执行快照（`Store.Snapshot`）都用当时的策略调用 `verify`；快照前把目录中记录的签名写回私有副本。`PublisherChanges` 只在安装时检查：Store 为每个包 ID 记录首次安装的发布者，卸载后保留，之后换发布者需要批准。

## Goals / Non-Goals

**Goals:**

- 精确批准的摘要单独足以建立信任，签名文件不改变结果。
- 摘要未被批准时，签名规则不变。
- 每次执行快照仍按当时的策略重新校验。

**Non-Goals:**

- 改变发布者授权、发布者撤销或 `PublisherChanges`。
- 改变包格式、签名输入或 CLI 信任文件。
- 由 Store 持久化摘要批准；策略仍由宿主每次提供。

## Decisions

### 摘要批准时不查看签名

批准的是确切内容。`signature.json` 不在摘要之内：带签名的副本若因签名被拒绝，删掉签名文件后的同一内容又会被信任。拒绝因此不提供保护，只让结果取决于一个谁都能改的文件。所以摘要被批准时，`verify` 在发布者检查之后直接信任，不读签名：签名缺失、密钥未知、已撤销、属于别的发布者、无法解码或验证失败都一样。

`signature.json` 仍须是结构正确的签名文档。它在信任之前由包检查（`readSignature`，严格解码）读取：不是 JSON、有重复或未知字段属于包格式错误，摘要批准也拒绝。摘要批准只跳过信任与密码学验证：密钥查找、撤销、发布者归属、签名值的 Base64 解码和 Ed25519 验证都在 `verify` 内，摘要被批准时都不执行。签名值不是合法 Base64 因此不算格式错误。

拒绝的备选：

- 只让未知密钥让位于摘要批准，已撤销密钥或验证失败的签名仍拒绝：同样删掉签名文件就能绕过，只多出分支。宿主要阻止某些内容，应撤回摘要批准或撤销发布者，这两者都作用在摘要覆盖的内容上。
- 另设生产用的摘要字段，`DevDigests` 继续只管未签名的开发包：两个字段表达同一件事（批准确切内容），区别只在包是否带一个不受摘要保护的文件。

### `DevDigests` 改名为 `Digests`

摘要批准现在是与 `Keys` 并列的生产信任来源，旧名会误导生产宿主。Cordis 处于 v0，本 change 已调整 Go API 行为，所以直接改名，不保留别名。调用方为 `cmd/cordis` 的 `run` 与 `dev`、`plugintest`、`packagehost.Store` 以及测试夹具。CLI 信任文件没有摘要字段，格式不变。

### 发布者规则先于摘要批准

ID 和发布者在摘要覆盖范围内，发布者撤销与授权对已批准的内容仍有意义，继续先于摘要检查。`PublisherChanges` 比较的是 Store 记录的发布者，与包靠签名还是摘要被信任无关。

### Development 与签名记录不变

安装仍把包带来的签名原样记入目录，快照把它写回私有副本并按当时的策略校验。Development 仍只标记目录导入，以及未签名、摘要被批准的归档；带签名、靠摘要被信任的归档不标 Development。它不是信任依据，信任在每次快照重新计算。`verify` 删去不再使用的 `development` 参数。

## Risks / Trade-offs

- [摘要被批准时，同一摘要带无效签名的再次安装会替换已记录的有效签名] → 只在之后撤回批准、改靠原签名时才有影响；宿主撤回批准前可重新安装带有效签名的归档。Store 不区分"验证过的签名"，避免为此增加第二种记录。
- [`cordis run -dev-unsigned` 和 `cordis dev` 现在也运行带未知密钥签名的本地产物] → 这两个命令批准的就是传入产物的确切摘要，结果与删掉签名文件后一致；`docs/cli.md` 随之改写。
- [只撤销签名密钥不再拒绝摘要被批准的包，只撤回摘要批准也不拒绝仍带有效受信任签名的包] → 文档说明快照在两者都不成立时才拒绝；要无条件阻止，撤销发布者或撤回它对该包 ID 的授权。
