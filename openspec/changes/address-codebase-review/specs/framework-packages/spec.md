# Spec Delta

## ADDED Requirements

### Requirement: 替换不改变持久启用意图
包替换退役旧实例时 SHALL 保留各 entry 的持久启用意图。替换在切换提交前失败、在重新启用前失败或宿主进程中断时，重开宿主后的 Restore MUST 仍按原启用意图处理这些 entry，不得把它们报告为停用。

#### Scenario: 切换提交失败
- **WHEN** 宿主替换一个有两个已启用 entry 的包，旧实例已退役而包选择提交返回非提交错误
- **THEN** 替换返回错误，两个 entry 的持久启用意图仍为启用；关闭并重开宿主后 Restore 启动它们

### Requirement: 包选择校验响应取消
包选择与替换在校验包内容期间 SHALL 响应调用方 context 的取消，取消后 MUST 不提交新选择并释放存储锁。

#### Scenario: 替换大包时取消
- **WHEN** 宿主替换一个接近展开字节上限的包，并在内容哈希期间取消 context
- **THEN** 替换返回取消错误，选定版本不变，其他存储查询不再等待该哈希完成

### Requirement: 执行副本不做逐文件持久同步
每次 activation 的私有执行副本与其他临时目录 SHALL NOT 对每个文件做持久同步；安装 MUST 在唯一提交点前保证内容已持久。

#### Scenario: 多文件包的重复启动
- **WHEN** 宿主多次启动同一个包含数百个资源文件的已安装包
- **THEN** 每次启动不对副本中的文件逐个执行持久同步，安装后的进程中断恢复语义不变

### Requirement: 发布者批准完成一次身份迁移
安装 SHALL 只以 catalog 保留的当前发布者判断身份变更；显式批准的新发布者在安装提交后成为当前发布者。旧发布者的已安装版本 MUST NOT 要求新发布者每次升级重复批准。签名信任、撤销、同版本不同摘要冲突仍 MUST 校验。

#### Scenario: 迁移后撤回一次性批准
- **WHEN** 新发布者经批准安装成功，旧发布者版本仍安装，宿主撤回迁移批准并安装新发布者下一版本
- **THEN** 安装成功，无需再次批准迁移；未经批准切回旧发布者仍被拒绝
